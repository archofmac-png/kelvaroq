Default changes are at final `inplace.rs:99,109` and `inplace/pool.rs:65`; per-feature
switches and commit/opening budgets remain available. No writer guard or fallback loop was
removed. The generation deletion is at final `shadow.rs:2459,2477-2480`.

The allocation saved per new placed resource is exactly
`8 * ((start + len).div_ceil(65536) - start / 65536)` bytes. The edge-page regression checks
zero capacity for the placed case versus two zero generations (16 bytes) for the copied
case. This is a construction saving, not an established recurring frame-time saving.

Default UMA avoids eligible shadow refreshes and constant upload fills by binding the same
physical bytes. Opening heaps and settling the directory also cost time. The net frame-time
delta is **unmeasured**. The previously reported >100 MB to <8 MB/frame result was supplied
by the user; it was not reproduced in this session.

the repository**, including ignored directories. Use the same engine, adapter, driver,

```powershell

  -KeysFile $keys -Runs 3 -Duration 300 -OutDir $runs -Label uma `
  -Baseline (Join-Path $runs 'legacy') -ExtraEnv @{}
```

Compare heavy-frame p50/p95 and draw-count buckets, submit work/waits, GPU busy, and draw/drop
ratios. Inspect `run*/engine.err.log` for `UMA section reads`, opening refusals, skipped
constant fills and private refresh requests. `monitor.rs:311-312` exports requested copy

bytes** (`host.rs:7468-7474`). Actual CPU copy byte counts feed `PREPARING` through
`host.rs:7619-7624` and appear in the frame log around `host.rs:8334`; these include fills
and explicit copies and must be interpreted alongside stage clocks. Do not infer physical
bus traffic from skipped-request counters.
