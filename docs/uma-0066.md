## Assessment before the fix

- **Correct: the race is real.** Baseline `host/uma.rs:37-44` tests `flying()`
  only while binding; `:79-116` binds mutable title bytes and retains resources,
  without preventing subsequent CPU writes. Resource lifetime is not byte immutability.
  The new gated GPU regression run against 0065 reads 256 overwritten bytes (`99`)
  instead of the submitted bytes (first word `31`, remaining bytes zero).
- **Correct: existing overlap disables the shortcut.** Baseline `host/uma.rs:38`
  returns on any flight, including unrelated readers. `host.rs:5962-5964` still
  calls the binder; `:7437-7449` subsequently performs the legacy fill. The check
  adds work there; its timing cost was not measured.
- **Correct: defaulting private constants contradicted the probe warning.**
  Baseline `inplace.rs:107-112` enables the policy despite costly openings. The
  stronger obstacle is already documented at `inplace.rs:34-37`: an opened address
  heap prevents changing the pages' protection. A guard-after-opening attempt this
  session reproduced `VirtualProtect` failure on WARP and was discarded.
- **Correct about upfront section commit, unproven about the claimed total cost.**
  `xmem.rs:534,567-580` selects `SEC_COMMIT` when it reserves a pool charge; the
  commit budget (`inplace/pool.rs:34-49`, default 8192 MiB) is distinct from the
  GPU-opening budget (`:9-18`, default 256 MiB). Neither proves a net benefit over
  reservation. Working-set pressure and TLB teardown deltas were not measured.
  The existing probe comments distinguish section opening (256 MiB, 0.2 ms, no
  working-set change) from private opening (70 ms, 256 MiB working set),
  `inplace.rs:13-28`; these are historical probe observations, not new timings.

## Delivered

1. `0066-01-constant-snapshots.patch`: replace mutable-page CBVs with immutable,
   list-owned scratch snapshots (`host/uma.rs:26-83`). Rebinding works with an
   existing flight. It copies once, initializes padding, and suppresses the old
   fill (`:61-82`; `host.rs:7436`). Callback/writer, replay and ownership guards
   remain (`host/uma.rs:36-46`). Scratch belongs to the detached recording through
   its fence (`host.rs:7113-7147`). Private constants require explicit
   `VICTORY_UMA_PRIVATE_CBV=1`, with the reason at `inplace.rs:107-114`.
2. `0066-02-pool-commit-policy.patch`: require `VICTORY_UMA_POOL=1`, with the
   commitment/cost reason at `inplace/pool.rs:63-70`. The allocator already
   falls back correctly when reservation fails (`xmem.rs:567-580`); extend its
   actual allocation test rather than changing that behavior (`:1480-1535`).

The first-write-guard candidate is not shipped: private openings prevent protection
changes, while physical `PageWindow` writes bypass title guards and notify only
after mutation (`xmem.rs:746-774,810-824`). A future direct path needs producer
write permits spanning those mutable windows and a compatible backing strategy.

This is a correctness repair. For each tested 256-byte constant, the GPU reads
**256/256 identical submitted bytes** after the source overwrite. One 256-byte CPU
copy replaces the unsafe zero-copy binding; the legacy fill is not also performed
(its poisoned destination remains unchanged, `host/uma.rs:233`). Rebinding consumes
256 additional bytes of logical scratch space in this fixture, not necessarily a
new committed allocation. General extra scratch use is `round_up(bytes, 256)` per
selected constant (`:60-62`). No frame-time, working-set or teardown improvement is
claimed. Both policies remain opt-in pending a measured benefit.
